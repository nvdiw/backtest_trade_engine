# فوکوس مستقل و تنظیم منابع اجرا

## فوکوس جدید

پروفایل `focused` از فایل قابل ویرایش [ma_focused.json](../param_grids/ma_focused.json) خوانده می‌شود. برای هر سمت ۱۲ پارامتر مستقل دارد؛ تغییر لانگ مقدار پارامتر شورت را تغییر نمی‌دهد. هر دو سمت روی همان حساب و محدودیت سرمایه معامله می‌کنند، بنابراین نتیجه مالی آن‌ها کاملاً مستقل نیست.

| گروه | کلید پس از پیشوند `long_` یا `short_` | کاربرد |
|---|---|---|
| میانگین‌ها | `ema_16_period`, `ma_50_period`, `ma_100_period`, `ma_200_period` | دوره واقعی میانگین؛ عدد داخل نام کلید الزام مقدار نیست |
| ورود | `entry_score_threshold` | حداقل امتیاز ورود |
| دوره اندیکاتورها | `period_adx`, `period_atr`, `period_atr_ma`, `period_vol_avg` | پنجره محاسبه اندیکاتور |
| فیلترها | `entry_adx_threshold`, `entry_atr_threshold`, `volume_spike_multiplier` | قدرت روند، نوسان و حجم |

برای مثال `long_ema_16_period: [14, 16]` و `short_ema_16_period: [20, 24]` بازه‌های متفاوت می‌سازند. مقادیر خروج، ریسک و وزن‌های امتیاز از فایل مبنا حفظ می‌شوند؛ MA و اندیکاتورهایی که در خروج هم مصرف می‌شوند طبیعتاً روی خروج نیز اثر دارند. پروفایل قدیمی با نام `focused_legacy` موجود است. `long_focused` و `short_focused` فقط پارامترهای همان سمت را جست‌وجو می‌کنند.

## منابع پردازشی

این گزینه‌ها در `optimize.py`، `evaluate_params.py` و `ma_strategy.py` موجودند. اجرای مستقیم MA یک استراتژی تک‌پردازشی است؛ انتخاب boost آن را موازی نمی‌کند.

| `--performance` | تعداد worker خودکار در optimizer/evaluator | اولویت Windows | مناسب برای |
|---|---|---|---|
| `power_saving` | یک‌چهارم پردازنده‌های منطقی، حداقل ۱ | Below normal | کار هم‌زمان با کامپیوتر |
| `normal` | نصف پردازنده‌های منطقی، حداکثر ۸ و حداقل ۱ | Normal | استفاده روزانه |
| `boost` | تعداد پردازنده‌های منطقی منهای ۱، حداقل ۱ | Normal | استفاده بیشتر از CPU و RAM |

`-w` یا `--workers` صریح، تعداد worker پیشنهادی را جایگزین می‌کند. این حالت‌ها سقف دقیق درصد CPU نیستند و تعداد تست‌ها، بازه‌ها، معیار انتخاب و دقت عددی را تغییر نمی‌دهند. برای داده یک‌دقیقه‌ای مصرف حافظه هر worker بیشتر است؛ انتخاب تعداد worker باید متناسب با RAM باشد. پس از توقف با Ctrl+C، همان فرمان را با حالت جدید اجرا کنید؛ سقف ۱۰۰، تعداد کل سیکل‌های کمپین است، نه ۱۰۰ سیکل اضافه در هر اجرا.

## فایل کندل و تشخیص تایم‌فریم

`--data-file PATH --timeframe auto` فایل انتخاب‌شده را به موتور، بررسی کیفیت داده و workerها منتقل می‌کند. انتخاب پیش‌فرض `auto` است و تشخیص از فاصله زمان‌های `Open time` انجام می‌شود، نه نام فایل. فایل ۱، ۵، ۱۵ دقیقه یا فاصله ثابت دیگر پشتیبانی می‌شود.

| قرارداد | رفتار |
|---|---|
| ستون‌ها | `Open time`, `Close time`, `Open`, `High`, `Low`, `Close`, `Volume` |
| زمان‌ها | تاریخ قابل خواندن، مرتب و بدون تکرار؛ برای epoch عددی ابتدا تبدیل لازم است |
| تشخیص | حداقل ۸۰٪ فاصله‌ها باید با فاصله غالب برابر باشند؛ سایر فاصله‌ها مضرب صحیح آن باشند |
| داده مختلط یا نامرتب | خطای روشن؛ یک تایم‌فریم منسجم در هر فایل استفاده کنید |
| `--timeframe 1m` | تطبیق فاصله واقعی با یک دقیقه؛ مغایرت خطا می‌دهد |
| دوره MA، warmup و cooldown کندلی | واحدشان تعداد کندل است؛ MA14 روی داده یک‌دقیقه‌ای خودکار به MA210 تبدیل نمی‌شود |
| تاریخ، مدت معامله و نرمال‌سازی سالانه | از زمان واقعی و فاصله کندل استفاده می‌کنند |

## شروع ۱۰۰ سیکل از برنده سیکل ۳۰۰

در ریشه پروژه این فرمان تک‌خطی در PowerShell یا CMD اجرا می‌شود:

```powershell
python optimize.py --auto --profile focused --base-source file --base-params "outputs/optimize/focused_recent_2y_50cycles/snapshots/cycles_000300/best_params.json" --data-file "data_candle/btc_15m_data_2018_to_2026.csv" --timeframe auto --performance normal --auto-cycles 100 --output-dir "outputs/optimize/focused_long_short_from300_100cycles"
```

پوشه جدید سیکل‌های ۱ تا ۱۰۰ خودش را دارد. checkpoint کمپین قبلی تغییر نمی‌کند. گزارش‌ها و snapshotهای خودکار در پوشه جدید ذخیره می‌شوند. Auto در اجرای دوباره همان پوشه را ادامه می‌دهد؛ grid ذخیره‌شده در checkpoint حفظ می‌شود، پس برای فوکوس یا فایل داده جدید پوشه کمپین جدید انتخاب کنید. این فرمان از سیاست پیش‌فرض ۲۴ ماه اخیر برای توسعه استفاده می‌کند؛ نتیجه آن آزمون مستقل خارج از نمونه نیست.
